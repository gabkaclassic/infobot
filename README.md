# infobot

Telegram-бот, который продаёт доступ к дереву информационных материалов. Оплата
проходит через ЮKassa, контент загружают администраторы текстовым файлом.

## Как устроено

Один процесс (`main.py`) запускает две задачи через `asyncio.gather`:

- **бот** на aiogram — опрашивает Telegram, отдаёт узлы дерева и кнопки;
- **приложение** на FastAPI — принимает вебхуки ЮKassa на `POST /infobot/payment`.

Приложение поднимается только при `PAYMENT_ENABLE=True`.

Дерево диалога разбирается один раз при старте и хранится в памяти. Состояние —
в Redis, три отдельные базы:

| База | Что хранит | Формат значения |
|------|------------|-----------------|
| 1 | доступ пользователей | `{"paid": bool, "confirmation_url": str}` |
| 2 | незавершённые платежи | `{"responsible": id, "target_user": id}` |
| 3 | состояние диалога | строка из `UserState` |

Ключ в базах 1 и 3 — ID чата Telegram, в базе 2 — ID платежа ЮKassa.

### Структура

```
main.py              точка входа
config.py            чтение переменных окружения с валидацией
logger_config.py     файловый логгер с ротацией
pyproject.toml       зависимости и настройки pytest
Dockerfile           образ приложения
docker-compose.yml   сервисы bot и redis
bot/
  bot.py             хендлеры aiogram и проверка оплаты
  setup.py           загрузка файла дерева администратором
  messages/          узел дерева и разбор текстового файла
payment/
  app.py             приложение FastAPI
  client.py          создание платежа в ЮKassa
  endpoints.py       вебхук ЮKassa

```

## Сценарии

**Обычная оплата.** `/start` → проверка записи в базе 1 → при отсутствии оплаты
создаётся платёж в ЮKassa, ссылка отправляется пользователю → ЮKassa шлёт вебхук →
`paid` становится `True` → пользователь получает корень дерева.

**Подарок.** `/gift` → бот переводит пользователя в состояние `GIVE_BOT` и ждёт ID
получателя → создаётся платёж, где плательщик и получатель доступа разные →
после оплаты уведомления уходят обоим. Если у получателя доступ уже есть, платёж
не создаётся. Состояние сбрасывается в любом случае, в том числе при ошибке ввода.

**Отмена.** Любое уведомление, кроме `payment.succeeded`, снимает признак оплаты —
но только если он ещё не был выставлен: уже оплаченный доступ не отзывается.

## Формат файла дерева

Одна строка — один узел, четыре поля через `|`:

```
идентификатор | текст | текст кнопки | имя картинки
```

- **идентификатор** — путь по дереву через точку (`teacher`, `teacher.age`).
  Родительский узел должен идти в файле раньше дочернего, иначе разбор упадёт.
  Первая непустая строка становится корнем, её идентификатор не используется
  (в существующем файле он пустой).
- **текст** — тело сообщения. `\n` в файле превращается в перенос строки.
  Спецсимволы MarkdownV2 экранируются автоматически.
- **текст кнопки** — подпись кнопки, ведущей к этому узлу.
- **имя картинки** — имя файла в `IMAGES_PATH` без расширения `.jpg`. Может быть пустым.

Все четыре разделителя обязательны даже для пустых полей:

```
| Добро пожаловать | | main_theme
teacher | В какую тему углубиться? | воспитатель | teacher
teacher.age | Про возраст | возраст |
```

Картинки перед отправкой уменьшаются до 5000 пикселей по стороне и сжимаются до
550 КБ.

Файл загружается администратором как документ `.txt` прямо в чат при
`SETUP_ENABLE=True`. Он разбирается во временный файл, и только при успешном
разборе заменяет `TREE_PATH`. Ошибка разбора оставляет прежнее дерево рабочим.

## Команды

| Команда | Кому | Что делает |
|---------|------|------------|
| `/start` | всем | проверяет оплату, показывает корень дерева |
| `/id` | всем | сообщает Telegram ID |
| `/gift` | всем | оплата доступа другому пользователю |
| `/free ID1 ID2 ...` | админам | выдаёт доступ без оплаты |
| отправка `.txt` | админам | загружает новое дерево |

Админы перечисляются в `ADMINS`. Команды администратора работают только при
`SETUP_ENABLE=True`.

## Переменные окружения

Задаются в `.env`, образец — `sample.env`. Обязательные переменные без значения
приводят к ошибке при старте с указанием имени переменной.

### Бот

| Переменная | Обяз. | По умолчанию | Назначение |
|------------|-------|--------------|------------|
| `BOT_TOKEN` | да | — | токен бота от BotFather |
| `ADMINS` | нет | пусто | ID администраторов через запятую |
| `SETUP_ENABLE` | нет | `False` | разрешить команды администратора |
| `TREE_PATH` | да | — | путь к файлу дерева |
| `IMAGES_PATH` | нет | `./images` | каталог с картинками |
| `GREETING` | нет | пусто | приветствие перед ссылкой на оплату |
| `GET_ID_INSTRUCTION` | нет | пусто | подсказка, как узнать чужой ID, для `/gift` |

### Приложение

| Переменная | Обяз. | По умолчанию | Назначение |
|------------|-------|--------------|------------|
| `HOST` | нет | `0.0.0.0` | адрес прослушивания, за локальным прокси — `127.0.0.1` |
| `PORT` | нет | `8000` | порт |
| `DEV` | нет | `False` | режим разработки |
| `FORWARDED_ALLOW_IPS` | нет | `127.0.0.1` | адрес реверс-прокси, см. ниже |

Булевы переменные считаются истинными при значениях `1`, `true`, `yes`, `on`
(регистр не важен). Любое другое значение, включая `False` и пустую строку, —
ложь.

### Оплата

| Переменная | Обяз. | По умолчанию | Назначение |
|------------|-------|--------------|------------|
| `PAYMENT_ENABLE` | нет | `True` | включить оплату и вебхук |
| `PAYMENT_ACCOUNT_ID` | да | — | идентификатор магазина ЮKassa |
| `PAYMENT_SECRET_KEY` | да | — | секретный ключ ЮKassa |
| `PAYMENT_COST` | да | — | стоимость доступа |
| `PAYMENT_DESCRIPTION` | нет | пусто | описание платежа и позиции чека |
| `PAYMENT_EMAIL` | нет | пусто | email покупателя в чеке |
| `PAYMENT_PHONE` | нет | пусто | телефон покупателя в чеке |
| `PAYMENT_WEBHOOK_URL` | нет | пусто | адрес возврата после оплаты |
| `PAYMENT_PRIVILEGED_USERS` | нет | пусто | ID с бесплатным доступом, выдаётся при старте |

Для чека по 54-ФЗ нужен хотя бы один контакт покупателя — `PAYMENT_EMAIL` или
`PAYMENT_PHONE`. Незаполненные контакты в чек не подставляются.

При `PAYMENT_ENABLE=False` оплата не проверяется, доступ открыт всем, приложение
FastAPI не запускается.

### Redis

| Переменная | Обяз. | По умолчанию | Назначение |
|------------|-------|--------------|------------|
| `DB_HOST` | нет | `localhost` | адрес Redis |
| `DB_PORT` | нет | `6379` | порт Redis |
| `DB_PASSWORD` | нет | пусто | пароль (`requirepass`) |
| `DB_USER` | нет | пусто | оставить пустым, см. ниже |

Redis из `docker-compose.yml` настроен через `requirepass` без ACL. В этом режиме
клиент должен слать `AUTH <пароль>` от имени пользователя `default`. Непустой
`DB_USER` заставит его слать `AUTH <пользователь> <пароль>` и получить
`invalid username-password pair`.

### Логи

| Переменная | Обяз. | По умолчанию | Назначение |
|------------|-------|--------------|------------|
| `LOG_LEVEL` | нет | `INFO` | уровень корневого логгера |
| `LOG_DIR` | нет | `logs/` рядом с проектом | каталог для файла лога |

`DEBUG` выводит в stdout запросы aiohttp, включая URL с токеном бота. На рабочем
стенде использовать не следует.

## Подготовка

```bash
cp sample.env .env      # заполнить значения
```

Файл по пути `TREE_PATH` должен существовать до первого запуска — без него бот
падает при старте на разборе дерева, а загрузить новое дерево можно только через
уже работающего бота. Для первого запуска достаточно файла с одной строкой:

```
| Здравствуйте | |
```

Каталог `logs/` создаётся автоматически. Файл дерева и картинки в репозиторий не
входят: `.gitignore` исключает `trees/*` и `*.jpg`.

## Запуск в Docker

```bash
docker compose up -d --build
docker compose logs -f bot
```

Поднимаются два сервиса:

- **redis** — порт публикуется только на `127.0.0.1`, доступ по паролю из
  `DB_PASSWORD`, данные в `./redisdata`;
- **bot** — собирается из `Dockerfile`, конфигурация целиком приходит из `.env`.

`docker compose up` завершится с ошибкой, если `DB_PASSWORD` не задан: пустое
значение означало бы `--requirepass ""`, то есть Redis без аутентификации.

Бот стартует только после того, как Redis пройдёт healthcheck, — иначе проверка
подключения при запуске приложения уронила бы контейнер.

### Сетевой режим

Сервис `bot` работает с `network_mode: host`, то есть делит сетевой стек с
хостом. Это не косметика, а требование проверки IP ЮKassa: в обычной bridge-сети
uvicorn видел бы вместо адреса nginx адрес шлюза docker, не признал бы его
доверенным прокси и отклонил бы **все** вебхуки с кодом 400.

Побочные следствия: `HOST` и `PORT` из `.env` — это порт на самом хосте, а
`DB_HOST=localhost` указывает на опубликованный порт Redis. Конфигурация nginx
при переезде в Docker не меняется.

### Данные и образ

Каталоги `trees/`, `images/` и `logs/` монтируются с хоста: дерево загружается
администратором в рантайме, картинки ведёт оператор. В образ они не попадают,
как и `.env` — секреты передаются через `env_file`.

Контейнер работает от пользователя с UID 1000. Если владелец смонтированных
каталогов другой, передайте свой UID при сборке:

```bash
UID=$(id -u) GID=$(id -g) docker compose build
```

Образ собирается на Python 3.12: под него у всех закреплённых версий есть готовые
колёса. На 3.13 `aiohttp` собирался бы из исходников и потребовал компилятор.

### Персистентность Redis

Используются снимки RDB — режим по умолчанию. Не добавляйте `--appendonly yes` в
команду сервиса: при старте с существующим `dump.rdb` и отсутствующим AOF Redis
загрузит пустой AOF и молча поднимется с чистой базой, потеряв все записи о том,
кто оплатил доступ. AOF включают на работающем сервере через
`CONFIG SET appendonly yes`, и только потом перезапускают.

## Зависимости

Объявлены в `pyproject.toml`: семь прямых в `[project.dependencies]` и четыре для
разработки в группе `dev`. Транзитивные разрешает pip, lock-файла нет — то есть
точные версии зависимостей второго уровня со временем меняются. Состав конкретной
сборки можно восстановить по артефакту `pip freeze`, который сохраняет каждый
прогон CI.

`[tool.setuptools] packages = []` — не опечатка: infobot запускается из каталога
с исходниками и в `site-packages` не ставится, поэтому `pip install .`
устанавливает только зависимости.

## Развёртывание за реверс-прокси

Вебхук ЮKassa принимается только с их диапазонов адресов — проверка идёт по
`request.client.host`. За реверс-прокси там оказался бы адрес самого прокси, и
все уведомления отклонялись бы с кодом 400.

Чтобы этого не произошло, прокси должен передавать `X-Forwarded-For`, а его адрес
должен быть указан в `FORWARDED_ALLOW_IPS`. Для nginx на том же хосте подходит
значение по умолчанию `127.0.0.1`. Если прокси в контейнере или на другом сервере,
укажите его адрес.

Пример для nginx:

```nginx
location /infobot/ {
    proxy_pass http://127.0.0.1:8000;
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    proxy_set_header X-Forwarded-Proto $scheme;
}
```

Отклонённый адрес пишется в лог строкой `Webhook rejected: IP ... is not in
trusted list` — по ней проверяется, что заголовок доходит.

### Ответы вебхука

ЮKassa повторяет уведомление, пока не получит ответ 200. Поэтому важно, чтобы
повторное уведомление по уже обработанному платежу тоже отвечало 200, а не ошибкой.

| Код | Когда |
|-----|-------|
| 200 | уведомление обработано; сюда же попадают повтор по уже закрытому платежу и событие, которое бот не обслуживает |
| 400 | недоверенный адрес или неразбираемое тело — повторять бессмысленно |
| 500 | временный сбой: Redis недоступен либо подтверждение не записалось |

Запись платежа удаляется при подтверждении и при отмене, поэтому повторное
уведомление по тому же платежу подтверждается без побочных действий. Сбой
отправки сообщения в Telegram на код ответа не влияет: доступ уже выдан,
повторять уведомление незачем.

## Тесты

```bash
pip install '.[dev]'
pytest
```

Тесты не требуют работающего Redis и не ходят в сеть: Redis подменяется на
`fakeredis`, ЮKassa и Telegram — моками. Переменные окружения задаёт
`tests/conftest.py`, файл `.env` при этом не используется.

## Логи

Пишутся одновременно в stdout и в `logs/log.log` с ротацией: до 500 КБ на файл,
3 файла истории. Каталог создаётся при старте.
